# WhereIsIt AI — нативный каталог отключённых дисков

**Текущая линия выпуска: 1.0.0-rc.3 — единый устанавливаемый кандидат, не принятый стабильный 1.0.**
Общее ядро — Rust, база — встроенная SQLite, Windows — Win32, macOS — SwiftUI/AppKit. Python, сервер базы данных и браузерный runtime обычному пользователю не нужны.

[Выпуски и установщики](https://github.com/i-shutov/whereisit-ai/releases) · [Состав rc.3](docs/releases/v1.0.0-rc.3.md) · [Фактическая приёмка](release/ACCEPTANCE.json) · [Актуальный HANDOFF](HANDOFF.md)

Windows-пакеты пока **без Authenticode-подписи**. macOS-приложения имеют локальную ad-hoc подпись, **не Developer ID и не нотарификацию Apple**. Предупреждения ОС и ограничения корпоративной политики не устранены. Не используйте кандидат как единственное хранилище каталога; сохраняйте оригиналы и резервные копии.

## Установка и основной сценарий

Выберите Windows x64 EXE либо macOS ARM64/Intel PKG или DMG на странице выпуска. Сверьте файл с `SHA256SUMS.txt`; версия и исходный коммит зафиксированы в `provenance.json`. Пакет для другой архитектуры не считается проверенной заменой.

Создайте **New catalog** или откройте существующий **Open catalog**. Для физического диска нажмите **Add disk**. Для исходного WhereIsIt CTF есть два разных режима:

- **Link CTF (read-only)** — поиск, дерево дисков/папок и экспорт из авторитетного внешнего CTF через производный индекс. При повторном использовании проверяется поколение SHA-256. Исходник не изменяется.
- **Import CTF** — отдельная копия в редактируемый SQLite-каталог. Изменения копии не означают изменения оригинального CTF и не доказывают совместимость изменённого экспорта с исходной WhereIsIt.

Выберите носитель, открывайте папки двойным нажатием. Глобальный поиск использует **All disks**; колонка **Disk** различает одинаковые пути на разных носителях. В редактируемом SQLite создавайте категории и назначайте их записям; категория папки применяется к потомкам при поиске.

## Возможности интегрированного кандидата

Каталогизация имён, структуры, размеров и дат; составной поиск; категории с наследованием; кандидаты в дубликаты; полный экспорт выбранной ветки, результатов поиска или списка кандидатов в **CSV, Parquet и JSON**. Экспорт связан с выбранным поколением CTF, не ограничивается текущей страницей и создаётся только в **новом файле**. JSON и экспорт дубликатов доступны из обоих нативных интерфейсов; старые блокировки этих элементов исправлены при интеграционной проверке rc.3.

**Duplicates** группирует по имени+размеру, только имени или только размеру. Это **кандидаты по метаданным, не доказательство одинакового содержимого**. Автоматического удаления нет. По умолчанию содержимое файлов не читается: без миниатюр, плагинов, разбора медиа и вычисления хэшей. На больших каталогах широкая группировка может быть медленной.

Пользовательские заметки/теги для linked CTF хранятся в **отдельной пользовательской SQLite**, не в производном кеше. Реализованы контроль ревизий, предварительная сверка после изменения CTF, явное подтверждение кандидата, отдельная активация/отзыв, проверенный просмотр и резервная копия с восстановлением только в новый файл. Неоднозначные или устаревшие соответствия остаются конфликтами; автоматического переноса нет. Просмотр заметок не подменяет поля исходного CTF.

Новые сканирования создают отдельные снимки, а не заменяют старые. Уже существующие в исходном CTF записи внутри архивов сохраняются; новые сканы архивы не распаковывают.

## Поиск

```text
(ext:mkv OR ext:avi OR ext:mp4) AND size:>1GiB
(ext:flac OR ext:mp3) AND NOT path:*/temp/*
name:*матрица* AND size:>=700MiB
category:"Музыка" AND ext:flac
description:концерт OR tag:favorite
```

Поддержаны `AND`, `OR`, `NOT`, скобки, поля `name`, `path`, `ext`, `size`, `description`, `tag`, `category`, кавычки и glob-маски. Пробел между условиями означает `AND`. Приоритет: `NOT → AND → OR`. `ext` сравнивается точно; `category` — по имени, не по полному пути категории. Текст сравнивается с Unicode lowercase, исходное написание сохраняется. Полные регулярные выражения, `XOR` и полное совпадение синтаксиса WhereIsIt не заявляются.

Размеры: `=`, `>`, `>=`, `<`, `<=`; `B`, `KB`, `MB`, `GB`, `KiB`, `MiB`, `GiB`, `TiB`. Условия без поля ищут по объединённым имени, пути, описанию и тегам каталога. FTS5 trigram отбирает кандидатов по фрагментам от трёх символов, затем проверяется точное условие. Короткие строки, широкие пути/категории и глубокие OFFSET-страницы могут быть заметно медленнее селективного поиска. GUI не требует полного COUNT перед первой страницей.

## Хранение и безопасный перенос

Новые каталоги используют **схему v3**: индексируемые поля находятся в `entries_core`, непустые описания/теги — в `entry_payload`. Для отсутствующего payload отдельная строка не создаётся. Представление вычисляет объединённый текст без второй полной копии; FTS5 поддерживается транзакционно. Запросы по горячим полям сначала выбирают ID страницы, затем подгружают её дополнительные данные.

Полные пути пока хранятся один раз на запись. Полные исходные CTF-записи остаются обратимыми бинарными данными; `opaque` — плотное исходное представление, не обязательно редкое расширение. DuckDB/Polars не встроены в продукт; DuckDB используется независимым QA-инструментом.

Существующие v1/v2 открываются без автоматической миграции. Сделайте резервную копию и выберите **Catalog → Create compact copy…** в Windows либо **Compact copy…** в macOS. Укажите новое имя. Исходная база подключается только для чтения; результат публикуется после сверки значений, категорий, исходных CTF-байтов, количества записей, внешних ключей, SQLite и FTS. Неизвестная таблица вызывает отказ, а не тихое удаление. Существующий файл и служебные `-wal/-shm/-journal` не заменяются.

Исходный каталог остаётся выбранным; новую копию откройте явно. Старые v0.1 бинарники не понимают v3. Нужен запас места для копии и журнала транзакции. Детальная отмена/прогресс уплотнения ещё не завершены; операция выполняется вне потока интерфейса.

```powershell
.\whereisit-ai-cli.exe --version
.\whereisit-ai-cli.exe validate 'C:\Catalogs\old.atlas.sqlite'
.\whereisit-ai-cli.exe compact 'C:\Catalogs\old.atlas.sqlite' 'C:\Catalogs\new.atlas.sqlite'
```

CLI в macOS находится внутри приложения:

```sh
'/Applications/WhereIsIt AI.app/Contents/MacOS/whereisit-ai-cli' validate "$HOME/Catalogs/catalog.atlas.sqlite"
```

## Фактические проверки

Общий Rust-набор, форматирование и Clippy, нативные Windows/macOS сборки, установщики и самостоятельные QA-регрессии проверяются в CI на точном коммите. Дополнительно выполняется реальное обновление установленной **rc.2 → rc.3** на Windows x64 и macOS ARM64/Intel с синтетическим пользовательским каталогом и проверкой его сохранности. Это не ручная приёмка Win10/11 или Mac GUI.

На **настоящем CTF с 44 дисками и 3 046 027 записями** выполнены импорт/целостность SQLite v3, контроль страниц поиска, полный экспорт и побайтовый CTF→SQLite→CTF. Независимая сверка CSV и Parquet совпала по всем **3 046 027 строкам и 15 полям**. В постоянном linked-сеансе проверены три формата выбранных результатов, полный экспорт кандидатов в дубликаты, отказы при устаревшем поколении/перезаписи и отдельное хранение/восстановление заметок. Оригинал не изменялся. [Обезличенный отчёт](docs/qa/RC3_REAL_DATA_REDACTED_20261031.json).

При полной SHA-проверке источника на запрос измеренный p95 составил **209,82–252,83 мс** на изолированном Linux, по десяти тёплым измерениям на запрос. Цель **150 мс не достигнута**; это также не аппаратная приёмка Windows/macOS. Историческая экономия размера **14,3%** вместо целевых 30% получена на [синтетическом наборе](docs/COMPACT_BENCHMARK_2026-10-28.md), а не подменяет реальные измерения.

Два ранее предоставленных исторических CTF найдены в библиотеке, но поставщик вложений отказывает в выдаче их исходных байтов. Их проверка не заявляется завершённой. Другие незакрытые условия: оригинальная WhereIsIt для изменённых CTF, ручные GUI/доступность/отмена, подписи и нотарификация, целевые SLO. [Точное состояние](release/ACCEPTANCE.json).

## Границы CTF

Поддержан исследованный **несжатый Catalog 3.00**, не любой CTF. Сжатие/шифрование и заполненные группы дисков отклоняются. Исходные категории и неизвестные поля сохраняются в бинарном представлении, но полное отображение в собственные категории не заявляется. Новые/изменённые CTF ещё должны быть приняты оригинальной WhereIsIt; собственный reader/writer этого не доказывает.

Новые категории/теги блокируют CTF-экспорт по умолчанию; технический `allow_lossy:true` требует явного согласия и возвращает флаги пропуска. В linked-режиме запись CTF запрещена. Экспорт полей CTF не подмешивает автоматически независимые пользовательские заметки из их отдельного хранилища.

Неизвестные расширения `0x10` сохраняются. **1 782 таких расширения нельзя называть потерянными описаниями** без спецификации/поведения исходной программы. DOS-даты сохраняются как исходное местное время без выдуманного UTC. CTF-импорт/экспорт пока материализует разобранный CTF в памяти; перенос SQLite и CSV/Parquet не требуют полного DataFrame.

## Сборка и выпуск

Rust **1.90.0** закреплён в `rust-toolchain.toml`, зависимости — в `Cargo.lock`.

```sh
cargo test --workspace --locked
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
```

Windows: MSVC + C++ Build Tools + Inno Setup 6.

```powershell
cargo build --release --locked -p atlas-windows -p atlas-cli
./installers/windows/build-installer.ps1
```

macOS 13+, Swift 5.9+/Xcode Command Line Tools:

```sh
bash apps/macos/build.sh
bash installers/macos/package.sh
```

`VERSION`, Rust-пакеты, приложение и установщики должны совпадать. Публикация из `main` разрешена только после успешных проверок точного SHA; пять установочных файлов повторно проверяются по контрольным суммам после загрузки в черновик GitHub Release. Публикатор допускает только **prerelease**, не стабильный 1.0, и не заменяет существующие теги/активы.
