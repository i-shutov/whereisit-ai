# WhereIsIt AI — нативный каталог отключённых дисков

**Текущая линия выпуска: 1.0.0-rc.2 — устанавливаемый кандидат, не стабильный 1.0.**
Общее ядро — Rust, база — встроенная SQLite, Windows — Win32, macOS — SwiftUI/AppKit. Python, сервер базы данных и браузерный runtime пользователю не нужны.

[Выпуски и установщики](https://github.com/i-shutov/whereisit-ai/releases) · [Что вошло в кандидат](docs/releases/v1.0.0-rc.2.md) · [Незакрытые условия стабильного выпуска](release/ACCEPTANCE.json)

Windows-пакеты пока **без Authenticode-подписи**. macOS-приложения имеют локальную ad-hoc подпись, **не Developer ID и не нотарификацию Apple**. Предупреждения ОС и ограничения корпоративной политики нельзя считать устранёнными. Не используйте тестовый кандидат как единственное хранилище каталога.

## Возможности

Каталогизация имён, структуры, размеров и дат; навигация по отключённым носителям; составной поиск; собственные категории с наследованием от папок; кандидаты в дубликаты по имени/размеру; экспорт всей выбранной ветки или результатов в CSV и Parquet; ограниченно совместимый CTF-импорт/экспорт.

По умолчанию содержимое файлов не читается: без миниатюр, плагинов, разбора медиа и вычисления хэшей. Совпадение метаданных — **не доказательство одинакового содержимого**; автоматического удаления дубликатов нет.

Новые сканирования создают отдельные снимки. Старый снимок не подменяется. Уже находившиеся в исходном CTF записи внутри архивов сохраняются, но новые сканы архивы не распаковывают.

## Что изменено в хранении

Новые каталоги используют **схему v3**:

- `entries_core` — индексируемые поля: идентификаторы, диск, родитель, имя, путь, тип, размер, даты и поисковые ключи.
- `entry_payload` — только непустые описания/теги. Для записи без payload отдельная строка не создаётся.
- Объединённый `search_text` больше не хранится второй строкой в каждой записи: его вычисляет совместимое представление. FTS5 поддерживается транзакционными триггерами.
- Обычные индексные запросы сначала находят идентификаторы страницы в компактной таблице; описания и теги читаются для выбранной страницы, если они не нужны самому фильтру.
- Полные исходные CTF-записи остаются обратимыми бинарными данными. Поле `opaque` парсера является плотным исходным представлением, а не обязательно редким расширением.

Полные пути пока хранятся один раз на запись. DuckDB/Polars не встроены в продукт: переход к другому движку не выполнен и не выдаётся за завершённый эксперимент.

### Безопасный перенос старого каталога

Существующие v1/v2 базы открываются без автоматической миграции. Сначала сделайте резервную копию. Затем:

**Windows:** меню **Catalog → Create compact copy…**.  
**macOS:** кнопка **Compact copy…**.

Укажите **новое имя файла**. Исходная база подключается только для чтения. Результат публикуется после сверки всех значений, категорий, исходных CTF-байтов, количества записей, внешних ключей, SQLite и FTS. Существующий файл и служебные `-wal/-shm/-journal` исходника не заменяются. Неизвестная таблица в исходной базе вызывает отказ, а не тихое удаление данных.

Оригинальный каталог остаётся выбранным. Для работы с новой копией явно откройте её через **Open**. Старые v0.1 бинарники не понимают схему v3; сохраняйте исходный файл для возврата. Нужен запас места для новой базы и журнала транзакции. Детальная отмена/прогресс этой операции ещё не закончены; она выполняется вне потока интерфейса.

CLI после установки Windows:

```powershell
.\whereisit-ai-cli.exe --version
.\whereisit-ai-cli.exe validate 'C:\Catalogs\old.atlas.sqlite'
.\whereisit-ai-cli.exe compact 'C:\Catalogs\old.atlas.sqlite' 'C:\Catalogs\new.atlas.sqlite'
```

CLI внутри macOS-приложения:

```sh
'/Applications/WhereIsIt AI.app/Contents/MacOS/whereisit-ai-cli' validate "$HOME/Catalogs/catalog.atlas.sqlite"
```

## Основной сценарий

Создайте **New catalog** либо откройте существующий **Open catalog**. Для физического диска нажмите **Add disk**. Для исходного WhereIsIt CTF есть два различных режима: **Link CTF (read-only)** — поиск и навигация по исходному файлу с проверяемым производным индексом, а **Import CTF** — отдельная копия в редактируемую SQLite. В связанном режиме исходный CTF не изменяется: редактирование категорий отключено, но CSV/Parquet-экспорт результатов поиска или выбранной ветки доступен **только в новый файл** через проверенную привязку к SHA-256 исходника. Запись CTF из linked-режима и перезапись файлов запрещены. Выберите носитель, открывайте папки двойным нажатием. Глобальный поиск использует **All disks**; колонка **Disk** различает одинаковые пути на разных носителях.

Выберите либо создайте категорию и назначьте её записи. Категория папки применяется к потомкам при поиске. **Duplicates** группирует по имени+размеру, только имени или только размеру. CSV/Parquet-экспорт выгружает всю выбранную область, не только страницу интерфейса. CTF-экспорт относится ко всему каталогу и может безопасно отказать при неподдержанных данных.

## Поиск

```text
(ext:mkv OR ext:avi OR ext:mp4) AND size:>1GiB
(ext:flac OR ext:mp3) AND NOT path:*/temp/*
name:*матрица* AND size:>=700MiB
category:"Музыка" AND ext:flac
description:концерт OR tag:favorite
```

Поддержаны `AND`, `OR`, `NOT`, скобки, поля `name`, `path`, `ext`, `size`, `description`, `tag`, `category`, кавычки и glob-маски. Пробел между условиями означает `AND`. Приоритет: `NOT → AND → OR`. `ext` сравнивается точно; `category` — по имени, не по полному пути категории. Текст сравнивается с Unicode lowercase, исходное написание сохраняется.

Размеры: `=`, `>`, `>=`, `<`, `<=`; `B`, `KB`, `MB`, `GB`, `KiB`, `MiB`, `GiB`, `TiB`. Условия без поля ищут по объединённым имени, пути, описанию и тегам. Полные регулярные выражения, `XOR` и полное совпадение синтаксиса WhereIsIt не заявляются.

FTS5 trigram отбирает кандидатов по фрагментам от трёх символов, затем проверяется точное условие. Короткие строки, широкие пути/категории и глубокие OFFSET-страницы могут быть существенно медленнее селективного поиска. GUI не делает обязательный полный COUNT перед показом первой страницы.

## Фактические проверки и ограничения

Новая схема и перенос покрыты 35 Rust-тестами. CI отдельно выполняет Windows MSVC-сборку и установку/удаление, macOS ARM64/Intel-сборки, проверку пакетов, установку PKG и команды встроенного CLI. Для конкретного скачиваемого пакета смотрите точный исходный коммит и результаты в `provenance.json`, а не только зелёный статус другой ветки.

[Синтетический замер 3 046 027 записей](docs/COMPACT_BENCHMARK_2026-10-28.md): размер уменьшен на **14,3%**, все проверенные значения при переносе, ID первой страницы и полные количества совпадений сохранились. Некоторые текстовые запросы стали медленнее; широкий запрос пути занимает около 2,3 с. Цель 30% уменьшения и все целевые задержки пока не достигнуты. Это **не измерение персонального CTF**, и его исходные бинарные записи в синтетический набор не включены.

Проведена независимая локальная проверка **реального CTF с 44 дисками и 3 046 027 записями**: импорт в SQLite v3, поиск, экспорт CSV/Parquet, целостность FTS5 и побайтовый CTF→SQLite→CTF завершились успешно. Начальный импорт с пакетной FTS-перестройкой занял 122,28–122,62 с против 338,10 с в контрольном варианте; результаты относятся к одному тестовому окружению, не являются p95 SLA. [Отчёт о выпуске](docs/releases/v1.0.0-rc.2.md). Исторические результаты: [VALIDATION.md](docs/VALIDATION.md).

## Границы CTF

Поддержан исследованный **несжатый Catalog 3.00**, а не любой CTF. Новые и изменённые файлы ещё должны пройти приём оригинальной WhereIsIt; собственный reader/writer и синтетические roundtrip-тесты этого не заменяют.

Сжатие/шифрование и заполненные группы дисков отклоняются. Исходные категории и неизвестные поля сохраняются в бинарном представлении, но их полное отображение в собственные категории не заявляется. Новые категории/теги блокируют CTF-экспорт по умолчанию; технический `allow_lossy:true` требует явного согласия и возвращает флаги пропуска. CSV/Parquet сохраняют собственные аннотации.

DOS-даты не имеют часового пояса. Они сохраняются как исходное местное время; точный UTC не выдумывается. CTF-импорт/экспорт всё ещё материализует разобранный CTF в памяти. Перенос SQLite и CSV/Parquet выполняются без загрузки всего каталога в DataFrame.

## Сборка и выпуск

Rust **1.90.0** закреплён в `rust-toolchain.toml`, зависимости — в `Cargo.lock`.

```sh
cargo test --workspace --locked
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
```

Windows: MSVC + C++ Build Tools + Inno Setup 6.

```powershell
cargo build --release --locked -p atlas-windows -p atlas-cli
./installers/windows/build-installer.ps1
```

macOS 13+, Swift 5.9+/Xcode Command Line Tools:

```sh
bash apps/macos/build.sh
bash installers/macos/package.sh
```

`VERSION`, Rust-пакеты, приложение и инсталляторы должны совпадать. Подготовительный workflow ограничен изолированной веткой разработки. Публикация из `main` разрешена только после успешных проверок одного точного SHA; пять установочных файлов проверяются по контрольным суммам после загрузки в черновик GitHub Release. Публикатор допускает только **prerelease**, не стабильный 1.0, и не заменяет существующие теги/активы.
