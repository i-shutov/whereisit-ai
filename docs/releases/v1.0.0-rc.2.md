# WhereIsIt AI 1.0.0-rc.2

**30 октября 2026 · релиз-кандидат для тестирования, НЕ стабильный 1.0.** Сборки нативные и полностью офлайн. Windows-инсталлятор **без Authenticode**, macOS подписана **ad-hoc**, не Developer ID и не прошла нотарификацию Apple. Установщики предоставлены в виде тестовых бинарников; ограничения ОС и политики безопасности не сняты.

## Что готово по сравнению с rc.1

- **Оригинальный CTF как независимый мастер.** Windows Win32 и macOS SwiftUI/AppKit получили отдельный режим *Link CTF (read-only)* наряду с импортом копии CTF в редактируемую SQLite. В связанном режиме доступна компактная навигация по дискам и папкам, поиск, ручное обновление поколения после внешнего сохранения. Исходный CTF никогда не открывается для записи.
- **SQLite 3.51.3** встроена вместо 3.46.0, включая исправление WAL-reset race. Все Rust-зависимости, лицензионные сведения и Cargo.lock согласованы; тестированы конкурирующие записи, checkpoint, rollback и аварийный выход процесса.
- **Собственная индексированная база SQLite v3** остаётся независимой от подключённых носителей. Пакетная транзакционная перестройка FTS5 при первом импорте ускорила загрузку на проверенном большом CTF с 338,10 до 122,28–122,62 с (около 2,76 раза). При ошибке импорт и состояние триггеров откатываются; уже заполненные БД используют обычные триггеры.
- **CTF SHA-256 и неизменяемые кэши.** Кэш определяется байтами исходника и рецептом индекса, а не названием или временем файла. Повторно сохранённый в оригинальном WhereIsIt CTF получает новое поколение; старые ID не считаются актуальными. Существующий связанный кэш только для чтения, пользовательские аннотации в нём не сохраняются.
- **Два режима запросов.** Строгий `ctf_search` целиком проверяет SHA-256 SQLite при каждом вызове. Резидентный `ctf_search_pinned` проверяет исходный CTF до/после каждого запроса, контролирует файловую идентичность производной SQLite и повторно хэширует её не реже чем через 60 с. Эти режимы имеют явно разные гарантии против активной подмены кэша.
- **CTF-диагностика** локализовала 1 782 кандидата с неподдерживаемым старшим байтом флагов `0x1C`. Неизвестные поля сохраняются побайтово; семантика дополнительного бита `0x10` не выдумывается.
- **Экспорт CSV/Parquet и метаданные дубликатов** сохранены. Дубликаты — только кандидаты по имени/размеру, не по хэшу содержимого; автоудаления нет.

## Фактическая приёмка на реальном CTF

В изолированном локальном окружении проверен один оригинальный CTF размером **144 766 574 байта**, с **44 томами и 3 046 027 записями**. Полный CTF → SQLite v3 → CTF выдал побайтово идентичный исходнику файл; контрольный SHA-256 исходника не изменился. Проверены счётчики томов, FTS5 integrity, foreign keys, пять? Нет: четыре фиксированных поисковых запроса, совпадение первых страниц/числа результатов, CSV и Parquet, связанная навигация по крупным томам и поиск MP3.

- Начальный импорт в пустую базу (оптимизированный FTS5): **122,28–122,62 с** на тестовом Linux. Это измерение, а не обещание для другого ПК.
- Построение и публикация защищённого поискового зеркала (с проверками): около **293,9 с**.
- Повторный строгий доступ к тому же кэшу: около **2,1–2,3 с**; отдельные pinned-запросы на исследованном CLI обычно **0,30–0,48 с**, включая SHA-256 CTF. Целевой p95 150 мс пока не достигнут.
- Исходные записи CTF, реальные имена файлов, пользовательские описания, SHA-256 источника, изображения медиатеки и производные пользовательские базы не попадают в GitHub, CI и релиз.

Пройденные платформенные CI-проверки включают Rust tests/fmt/Clippy, Windows x64 MSVC + Inno Setup install/CLI/uninstall, macOS ARM64 и Intel .app/PKG/DMG + installed CLI + проверку сохранения каталога. Наличие зелёных CI-сборок **не эквивалентно** ручной UI-приёмке на физическом экране.

## Установка и миграция

Доступны пять файлов: `WhereIsItAI-1.0.0-rc.2-windows-x64-setup.exe`, а также `WhereIsItAI-1.0.0-rc.2-macOS-arm64.pkg/.dmg` и `WhereIsItAI-1.0.0-rc.2-macOS-x86_64.pkg/.dmg`. Сверьте SHA-256 по `SHA256SUMS.txt` и источник сборки в `provenance.json`.

Перед установкой обновления сохраните резервную копию собственных SQLite-каталогов и CTF. Установщик не должен удалять пользовательскую базу. Старые v1/v2 SQLite не заменяются при открытии; команда **Compact copy** создаёт новую проверяемую v3-копию. Связанный CTF не является местом для редактирования нативных категорий или тегов.

Команда диагностики встроенной версии: `whereisit-ai-cli --sqlite-version` → `3.51.3`.

## Что всё ещё блокирует стабильный 1.0

- Проверка **изменённого/нового CTF именно в оригинальном WhereIsIt**; несжатый Catalog 3.00 исследован, сжатие/шифрование и некоторые группы/категории не реализованы.
- Семантика 1 782 полей описания с флагом `0x1C`; пока они сохраняются, но не все доступны для полнотекстового поиска.
- Стабильное редактирование нативных аннотаций и категорий поверх linked-CTF, согласование конфликтов после внешних изменений.
- Ручной end-to-end GUI/DPI/доступность на Windows 10/11 и macOS 13+, установка поверх предыдущего RC, прогресс/отмена всех длительных операций, подтверждение SLO быстрого поиска.
- Windows Authenticode, Apple Developer ID/нотарификация, а также отдельные тесты двух исторических CTF e-books/MP3.

**Стабильный выпуск запрещён:** `release/ACCEPTANCE.json` содержит `stable_ready=false`. Доступные бинарники предназначены для тестирования. Данные приватных каталогов в них не включены.
