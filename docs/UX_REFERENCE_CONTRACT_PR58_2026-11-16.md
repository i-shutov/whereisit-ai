# PR #58 — канонический UX-прототип WhereIsIt AI

**Принято 16 ноября 2026 г.** Владелец продукта указал [PR #58](https://github.com/i-shutov/whereisit-ai/pull/58) и исходный коммит `a899ac4b3e6db482e5e533e350924bc81547ddbf` как **тот прототип, на котором он хочет продолжать работу**. Папка `apps/ui-prototype/` является основной средой разработки UX и функциональной моделью будущего native-приложения. Эта фиксация **выше по приоритету**, чем исторические наброски Win32/SwiftUI из PR #57.

Состояние репозитория: PR #58 (React + TypeScript + Express) слит в `main` коммитом `5b421e9d2b779923765459464cd5987c27baaed7`; post-review safety fix `202970d7206b8e0754e44df48f74a47f1cf2b7fb` сохраняет каноническую компоновку, но исключает **реальное удаление файлов и готовые скрипты очистки**, поскольку метаданные не доказывают резервную копию. Оригинальная версия доступна по tag/commit `a899ac4` для сравнения. Прототип — исполняемое приложение с **симулированными данными**, пока не полноценный Rust/egui.

## Каноническая композиция — сохранить

1. **Верхняя шапка/основные действия:** компактная навигация по каталогу и функциям, выбор RU/EN, поиск по всем дискам.
2. **Левый реестр:** одна компактная строка на каждый из 60+ USB-дисков; пункт «Все диски каталога», идентификатор, читаемая метка, заполнение и свободное место. Быстрый фильтр и сортировка.
3. **Центральная рабочая область:** виртуализированная таблица результатов, разумная плотность строк, заметные колонки «диск», путь, размер, формат и видеополя *только когда они действительно известны*.
4. **Контекст выбранного файла:** инспектор и быстрый переход к каталожному диску, папке, данным о носителе, альтернативным экземплярам. Переходы не должны терять выделение/прокрутку/поисковый запрос.
5. **Свойства диска:** F2 / двойной клик / модальное окно для названия, наклейки, заметок и реальных записанных параметров. Наклейка ≠ подтверждённая ОС-идентичность.
6. **Отдельные пространства:** аналитические срезы архива, круговая sunburst-диаграмма, локальный анализатор (режим просмотра). Исходные механизмы и безопасность — не из визуальной демо-БД.
7. **Сценарий видеоархива:** 60 USB, преимущественно видео; уровни совпадения — по метаданным, частичные сигнатуры, затем только независимо проверенные полные хэши; не продавать предположения как побайтовые равенства.

Ни PR #57, ни существующий Win32/SwiftUI UI не разрешают менять эти базовые UX-решения без явного согласования и сравнительного visual review.

## Схема разработки: прототип → контракт → Rust/egui

| Шаг | Где работа | Контроль |
|---|---|---|
| UX-итерация | `apps/ui-prototype/src`, `apps/ui-prototype/server.ts` (симуляция) | TypeScript/Bun build, скриншот-атлас по сценариям, сравнение с PR58, отсутствие внезапной перестройки и разрушительных команд |
| Контракт | `docs/UX_REFERENCE_CONTRACT_PR58_2026-11-16.md` и Rust service API | Маппинг каждого действия к `atlas-service`, реальный статус данных и failure states, тесты с синтетическими fixture |
| Native перенос | `apps/desktop-egui` (новый Rust crate) | Экран и поведение должны соответствовать PR58; `SidePanel`/виртуальная `TableBuilder`/инспектор, без React/Node в поставке |
| Приёмка | Win10/11 + Mac ARM/Intel, маленькое окно/HiDPI/клавиатура/USB | UX-атлас, измерение кликов и пути мыши, end-to-end 3M каталог, отсутствие несогласованного редизайна |

### Функциональная трассировка

|---|---|---|

| Импорт/экспорт, категории, снимки, аннотации | Устоявшийся Rust core/service | **Backend ready in tested scope; egui frontend pending** |

## Неприкосновенные инварианты

- Прототип может продолжать существовать как веб-редактор и интерактивный тест-дизайн; не объявлять его production browser-runtime без отдельного продуктового решения.
- PR58 — визуальный и поведенческий источник истины, PR57 — функциональный донор и тестовая архитектурная база. При конфликте UI дизайн PR58, при конфликте корректности/безопасности — проверенные сервисные инварианты и fail-closed поведение.
- Никаких автоматических удалений, скриптов очистки, подстановки вымышленных USB-статусов, недоказанных «байт-в-байт» копий.
- Замеры мышекликов/пути курсора и адаптивности делаются по **существующим** сценариям PR58, а не по изобретённому альтернативному макету.
- Готовность каждого будущего релиза принимается отдельно по точному SHA и его платформенному scope. Выпущенная Windows 1.0 имеет `stable_ready=true`; отсутствие подписи согласовано владельцем. Это не разрешение автоматически менять readiness или политику подписи следующих релизов.
