## 1. Суть продукта и границы

WhereIsIt AI — **офлайн-каталогизатор** содержимого десятков подключаемых USB-дисков. Приоритетный сценарий: найти файл на отключённых носителях → определить **точный каталоговый диск**, который нужно принести с полки → посмотреть возможные копии. Сведения из каталога — записанные метаданные; они сами по себе не доказывают присутствие диска, доступность файла или байтовую идентичность дубликатов.

Реализованы нативный Win32/Rust UI и SwiftUI/AppKit, общая Rust-служба и ABI, SQLite 3.51.3 с hot/cold индексируемым ядром, CTF-импорт/экспорт, полнотекстовый/логический поиск, дерево дисков, категории, кандидаты в дубликаты, CSV/Parquet/JSON. Программа не должна читать содержимое файлов на носителях, вычислять хэши содержимого или удалять дубликаты без отдельного явного сценария.

В **linked CTF** исходный файл остаётся авторитетным, читается без изменений; производный SQLite-кэш привязан к SHA-256 оригинала, парсеру и версии индексов. Параллельные пользовательские категории/заметки лежат в отдельном долговечном хранилище, а не в одноразовом кеше. Изменение оригинала требует переидентификации поколения и явного разрешения конфликтов, не автоматического предположения о совпадении записей.

## 3. Доказательная приёмка реального CTF

Испытан **подлинный пользовательский CTF**: **44 тома, 3 046 027 записи**. Источник обрабатывался локально, в публичные GitHub/CI-артефакты не загружался. Эти результаты относятся к зафиксированному Linux RC3 executable source commit `fedc833b19c69428ad3f22d4fa2e2c0a9582a07a` и его документированному эквивалентному CLI; перенос выводов на другие OS/физические GUI невозможен без отдельных испытаний.

| Проверка | Результат и граница доказательства |
|---|---|
| CTF → SQLite → CTF (неизменённый источник) | **PASS**, байтовая идентичность и отсутствие записи в оригинал |
| CSV vs Parquet, все 15 полей | **PASS** для **3 046 027 / 3 046 027** записей независимым считыванием |
| First/second page, counted/fast | **PASS** на проверенных реальных запросах |
| Selected linked CSV/Parquet/JSON | **PASS**, **12 664** записей, все поля |
| Полный экспорт metadata duplicates | **PASS**, **32 757** кандидатов, сверка членства независимым SQL |
| SHA-generation invalidation, no-clobber | **PASS**, stale-generation отказывается от вывода, источники/кеш не меняются |
| Отдельные user annotations, revision CAS, snapshot restore | **PASS** в заявленном Linux сервисном сценарии |
| Первичная синхронизация CTF, измерение | **170,471 секунды** на отдельном Linux сценарии; не обещание для всех машин |
| Скорость warmed query с полным SHA источника | p95 по трём запросам **218,60 / 209,82 / 252,83 мс** (по 10 измерений) |
| Целевой p95 ≤150 мс | **НЕ ДОСТИГНУТ**, физический Windows/macOS benchmark отсутствует |

Источник агрегатов: `docs/qa/RC3_REAL_DATA_REDACTED_20261031.json` из исходного дерева `main`; приватные source file hashes, пути, имена и файлы намеренно исключены.

Важная интерпретация opaque CTF: **1 782** записей с type-1 расширением и высокими флагами `0x1c` не означают доказанную потерю 1 782 текстовых описаний. Семантика дополнительного бита `0x10` неизвестна, байты сохраняются opaque; нужен первичный разбор оригинальной программы/спецификации.

## 5. Особо важное расхождение: тег RC3 и `main`

Опубликованный тег **`v1.0.0-rc.3` → `5d91ba12adfa46f5ec4eb26bdf8e08b590b60f3c6`**. После публикации была исправлена **гонка интеграции защиты приватных данных**, и текущий `main` стал **`cabdb3d2b139a67729a795ba9c34e4d3144c9c9f`**. Следовательно, релизные `.exe/.pkg/.dmg`, опубликованные под RC3, привязаны к **старому tag** и нельзя приписывать им более поздний privacy gate. Это не означает, что там содержатся приватные данные: publisher RC3 завершился успешно и проходил предусмотренные ему проверки. Но следующий релиз должен быть построен на новом точном SHA и с полной release privacy проверкой. **Не передвигать существующий RC3 tag.**

## 6. Нерешённые условия для стабильного 1.0

1. **Оригинальная WhereIsIt:** реально открыть/прочитать **изменённый или новый CTF** из нашего writer в изолированной Windows-среде; байтовый roundtrip неизменённого CTF недостаточен.
2. **Исторические вложения:** файлы `e-books.CTF` и `Mp3-60Gb.CTF` ранее предоставлены, но у предыдущего исполнителя не было разрешённого доступа к их raw bytes через провайдера. **Не говорить «не предоставлены»** и не подменять синтетикой; при открытии доступа выполнить персональную локальную QA.
3. **Физический UI:** Win10/11, macOS ARM64/Intel; 1366×768, DPI/Retina, keyboard/focus, screen reader, install/upgrade/uninstall, GUI screenshot atlas, работа при отключении и повторном подключении USB, clone UUID и physical pairing.
4. **Криптографическая подпись:** Windows Authenticode, Apple Developer ID Application+Installer, notarization/Gatekeeper. Сейчас кандидаты unsigned/ad-hoc.
5. **Производительность:** p95 150 мс на реальном большом каталоге без отключения SHA-защиты; GUI прогресс/отмена, быстрые страницы дубликатов, потребление памяти/диска, тесты на каждой OS. Отдельная метрика времени первого построения индекса также требует работы.
6. **CTF opaque 0x10/0x1c:** установить семантику по первичному источнику; не интерпретировать поля как пропавшие описания без доказательства.
7. **PR #57:** архитектурный USB-locator/поисковый UX пока не слит; работоспособность физического диска не доказана реальным оборудованием, даже при зелёной CI.

**Решение о выпуске:** RC3 — usable unsigned prerelease с масштабной реальной backend-приёмкой; **stable release GO = NO**.
