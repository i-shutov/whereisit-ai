# WhereIsIt AI — roadmap после Windows 1.0

Обновлено 26 ноября 2026 г. Это актуальный план продукта; прежние планы до 1.0 сохранены как история.

## Windows 1.1.1 — финальная проверка публикации

Стек #94–#101 интегрирован; прямое открытие CTF, дерево и поиск приняты в
установленном Windows-кандидате. Обе стороны обмена с оригинальной WhereIsIt
прошли на копии полного каталога: 3 046 133 строки, ровно одна ожидаемая правка
описания. Две серии поисковых замеров дали худший p95 122,112 мс. Установка,
перезапуск и сохранность внешних данных проверены; прежние P1 исправлены в 1.1.1.
[Точные артефакты, покрытие и ограничения](qa/WINDOWS_1_1_1_STABLE_ACCEPTANCE_20261126.md).
Публикация — после CI и GUI точного итогового установщика из main; старые теги
и файлы неизменны. Пик памяти около 863 МиБ и точный Win10 повтор остаются
последующими задачами; macOS/Linux выпускаются отдельно.

Ниже сохранена история измерений и этапов, а не актуальный список открытых P1.

## Текущий приоритет — быстрое открытие CTF после выпуска 1.1.0

**Коррекция владельца 24.11.2026:** приоритет — открытие каталога как списка дисков
с деревом папок, а не глобального списка имён. Общая сортировка больше не является
следующей задачей. Восстановить сценарий диск → папка → файл с контекстом,
breadcrumbs/Up/Back и точным переходом из поиска в дерево: сначала в PR58,
затем в Rust/egui. [Контракт и фактическое наблюдение оригинала](qa/CATALOG_TREE_NAVIGATION_20261124.md).

**Checkpoint 26.11.2026:** сценарий диск → дерево → файл реализован сначала в
PR58, затем в Rust/egui; на `aa8b37d` прошли финальная нативная проверка позднего
предка после загрузки соседей, двойной щелчок и все 17 CI checks. На полной
защищённой копии подтверждены реальная отмена активного поиска и успешный повтор.
Свежий Rust service benchmark: открытие 2,392 с, через первый поиск 5,545 с;
30 повторов на класс, p95 обычного текста 275,485 мс, отсутствующего текста
3148,377 мс, пик working set 734,06 МиБ. Это не установленный hotfix и не
Windows 10 PASS; P1 остаётся открыт. Следом — измеренные затраты полных сканов,
проверка операций, offline installer и сохранность данных при обновлении 1.1.
[Результаты и ограничения](qa/CTF_HOTFIX_PROGRESS_20261126.md).

**Следующий checkpoint 26.11.2026:** Windows read-only pin убирает повторное
полное чтение CTF перед/после запросов; при невозможности защиты сохраняется
полная SHA-проверка. На `caec14f`: открытие 1,366 с, вместе с первым поиском
3,601 с; p95 обычного текста 41,592 мс, отсутствующего пути 2353,349 мс.
Peak working set 862,79 МиБ выше прежних 734,06 МиБ; рост памяти остаётся
открытым наблюдением. P1 не закрыт, stable readiness не меняется.
[Реализация, регрессии, замеры и ограничения](qa/CTF_SOURCE_READ_PIN_20261126.md),
[текущие GUI/CI результаты PR #98](https://github.com/i-shutov/whereisit-ai/pull/98).

Windows [1.1.0 опубликован](https://github.com/i-shutov/whereisit-ai/releases/tag/v1.1.0), но выявлен **P1-CTF-COLD-OPEN**: на Windows 10 владельца каталог около 140 MB не открылся за 15 минут. Прежняя функциональная приёмка и тёплый поиск по готовой SQLite не подтверждали скорость первого открытия. Утверждение об отсутствии P0/P1 в историческом checkpoint ниже больше не актуально. [Дефект и исправление оценки](qa/CTF_COLD_OPEN_DEFECT_20261124.md). Тег и опубликованные файлы не заменяются; `stable_ready=false`.

**Checkpoint к hotfix 1.1.1, PR #99:** первая страница в порядке
каталога больше не ждёт глобальной сортировки. После прототипа тот же запрос
перенесён в egui. На `dbff8f8` открытие вместе с первым поиском заняло 1,645 с
против 4,309 с в прежнем порядке одним бинарником. GUI на 60 дисках прошёл
страницы, контекст и возврат из папки. Пик памяти не снизился; p95 обычного
текста 234 мс и отсутствующего текста 1249 мс всё ещё дают **FAIL SLO 150 мс**.
[Подробные замеры и ограничения](qa/CTF_CATALOG_FIRST_PAGE_20261126.md).
Следующие шаги: сократить стоимость полных сканов и повторную проверку имени
в пути, отдельно измерить временную память парсера; затем интегрировать стек
PR с проверкой diff/CI, проверить точный установщик 1.1.1 и обновление с 1.1.
Stable и новый тег — после этих проверок; текущие опубликованные файлы неизменны.

**Текущий checkpoint, PR #100 (`24d7e77`):** убрана повторная проверка имени,
добавлены ограниченный кеш предков и обработка порций максимум четырьмя
работниками. Две независимые серии по 30 повторов на каждый из десяти классов
дали **PASS p95 ≤150 мс**: худший p95 122,112 мс, обычный текст около 29 мс;
открытие вместе с первым поиском 1,273 / 1,217 с. Пик памяти при открытии не
объявляется исправленным. [Замеры, тесты и границы покрытия](qa/CTF_TEXT_SCAN_20261126.md).
Следом — завершить точный CI и GUI (для первого захвата потребовалось повторное
RDP-подключение), интегрировать #94 → #95 → #96 → #97 → #98 → #99 → #100,
проверить операции, точный установщик 1.1.1 и обновление установленной 1.1.
`stable_ready=false` до проверки кандидата; выпущенные теги и файлы неизменны.

1. **Реализовано в экспериментальной ветке:** открытие и поиск по неизменяемому снимку CTF без обязательного импорта, FTS или фонового преобразования в SQLite. Сохранены общий язык запросов, страницы, экспорт и кандидаты по метаданным; SQLite остаётся хранилищем собственных каталогов и пользовательского состояния.
2. **Измерен нативный прототип DuckDB:** чтение порций из Rust-снимка напрямую, без Python/Parquet. На 3,046 млн записей открытие с первым поиском — 2,412 с; сверка десяти классов запросов с SQLite пройдена. Rust быстрее для части повторных страниц, DuckDB — для ряда полных сканов. [Сравнение и фактический GUI-checkpoint](architecture/NATIVE_DUCKDB_CTF_PROTOTYPE_20261124.md). Выбор единственного исполнителя пока не обоснован.
3. **Прямые агрегаты реализованы в следующей экспериментальной ветке:** карта/sunburst и разрезы используют Rust-снимок без native-импорта; полные ответы сверены с SQLite, p95 четырёх сценариев 340–784 мс. В GUI проверены контекст рабочих пространств, переход в поиск, отмена и повтор. Исправлен также существующий P1 подсветки описаний/тегов в SQLite; установленный 1.1.0 ещё затронут. [Измерения, GUI и оставшиеся проверки](qa/DIRECT_CTF_ANALYTICS_20261124.md).
4. **На измеренной копии сокращена лишняя ёмкость массивов записей:** отдельное изменение запрашивает уплотнение snapshot перед публикацией; результат зависит от аллокатора. На полном каталоге GUI private bytes уменьшились примерно на 205 МиБ; это не обещание снижения working set/пика. [Метод, результаты и ограничения](qa/CTF_SNAPSHOT_CAPACITY_20261124.md). Следом: сократить повторные аллокации/нормализацию, проверить маршрутизацию запросов и повторить одинаковые end-to-end замеры. Проверить безопасный явный переход к редактированию, которому пока нужен native-импорт. Сохранить UX PR58 и переносимый Rust. Полная новая копия строк в RAM не должна появляться без измеренного выигрыша.
5. **До hotfix stable:** точный CI, GUI-отмена поиска, проверка всех операций и офлайн-установщика, обновление установленной 1.1 с сохранностью внешних данных. Windows 10 нового артефакта отмечается отдельно; текущие Windows 11 service/GUI результаты не подменяют её. Исходные CTF только для чтения, публичная проверка только на синтетике.

## Windows 1.1 — история функционального выпуска

Ниже сохранён checkpoint функций и первоначальной приёмки. Публикация 1.1.0 уже выполнена; текущий открытый P1 и очередь hotfix перечислены выше.

Вкладки/рабочие пространства, sunburst и локальный анализатор входят в следующий релиз. Дата пока не назначена. UX задаёт **[PR #58](https://github.com/i-shutov/whereisit-ai/pull/58)** (`apps/ui-prototype/`, исходный `a899ac4`), [контракт PR58](UX_REFERENCE_CONTRACT_PR58_2026-11-16.md). Развитие сценариев начинается в этом прототипе с демонстрацией и визуальной приёмкой, затем переносится в Rust/egui с тем же поведением. React/Express остаётся моделью UX и не входит в продуктовый runtime.

| Очередь | Пакет работ | Критерий завершения |
|---|---|---|
| 1 | Вкладки и рабочие пространства PR58 | Переключение между каталогом и аналитическими представлениями сохраняет каталог, запрос, scope, выбранную строку, папку и прокрутку. Состояния загрузки, ошибки и закрытия проверены на реальном сервисе; 60+ дисков, клавиатура и малое окно приняты в GUI. |
| 2 | Срезы архива и sunburst PR58 | Read-only агрегирующий API Rust/SQLite вместо демонстрационных значений; размеры/счётчики сверены с контрольной выборкой, переход сегмент → ветка и возврат сохраняют контекст. Явно определено включение вложенных/архивных записей, без двойного счёта. Длительные вычисления вне UI-потока, с отменой и измерением памяти/задержки на большом каталоге. |
| 3 | Локальный анализатор PR58 | Только явно выбранная пользователем папка/носитель, метаданные и режим просмотра; прогресс, отмена, ошибки доступа и symlink проверены. Сверка с каталогом показывает кандидатов по метаданным, а не доказанные резервные копии или равенство байтов. Экспорт создаёт новый файл; удаления и скриптов очистки нет. |
| 4 | Интеграция и выпуск 1.1 | Трассировка прототип → service API → egui, синтетические регрессии, точный CI, реальный установленный Windows GUI, обновление 1.0 → 1.1 с сохранением внешней SQLite/заметок/категорий, отмена/rollback, контроль CTF и полных экспортов. |

Общую оболочку вкладок согласовать первой. Sunburst и анализатор затем могут разрабатываться независимо, используя проверенные сервисные контракты. Демонстрация прототипа, реализованный backend и принятый native GUI отмечаются разными статусами; запланированная функция не считается выполненной.

Первый этап слит в main в [PR #87](https://github.com/i-shutov/whereisit-ai/pull/87): сохранение контекста в прототипе и native Search/Disks принято в реальном GUI на 60 синтетических дисках; точный CI прошёл. [Sunburst и разрезы](qa/WINDOWS_1_1_ANALYTICS_PR58_20261123.md) слиты в [PR #88](https://github.com/i-shutov/whereisit-ai/pull/88), затем после переноса на main и проверки diff/CI слит локальный анализатор [PR #89](https://github.com/i-shutov/whereisit-ai/pull/89). Для анализатора пройдены прототип → браузер → Rust/service → синтетические native GUI-сценарии; [матрица](qa/WINDOWS_1_1_LOCAL_ANALYZER_PR58_20261123.md) отдельно перечисляет фактические PASS и оставшиеся проверки. Кандидат 1.1.0-rc.1 принят в установленном GUI: обновление опубликованной 1.0, перезапуск, удаление, rollback и повторная установка прошли; внешние SQLite, заметки, категории и отдельные свойства дисков сохранились побайтово. На точном main `b5e3667` прошли 14 checks / 6 workflows. [Очищенный результат PR #90](https://github.com/i-shutov/whereisit-ai/pull/90) дополняет [протокол](qa/WINDOWS_1_1_INSTALLED_UPGRADE_20261123.md). Подтверждённых оставшихся P0/P1 в Windows scope нет. План функций Windows 1.1 выполнен; финальная публикация stable проводится отдельным явным процессом после проверки пересобранного установщика и CI. Windows 1.0 и его артефакты сохранены; macOS/Linux остаются отдельными выпусками.

Поддержка 1.0.x идёт отдельно: воспроизводимые дефекты целостности, CTF, поиска и установки исправляются с синтетической регрессией и проверкой затронутого сценария. Функциональность 1.1 не возвращается в закрытые гейты Windows 1.0.

## macOS — отдельный выпуск, версия и дата не назначены

- Сохранять общий Rust/SQLite/service слой и существующий платформенный код; продолжать полезные compile/tests для Apple Silicon и Intel. Успешный CI не считать физической GUI-приёмкой.
- Довести Rust/egui UX по PR58, проверить интеграцию с ОС, файловые диалоги, клавиатуру, Retina/доступность и длительные операции на реальных Mac.
- Отдельно принять install → launch → catalog/search/export → upgrade/uninstall с сохранностью внешних каталогов на обеих заявленных архитектурах.
- Определить политику Developer ID/нотаризации для этого выпуска; разрешение на неподписанный Windows 1.0 не распространяется автоматически на macOS.

Этот выпуск не блокирует Windows 1.1 и не объявляется готовым по старым SwiftUI-сборкам или пакетам RC.

## Linux — отдельный выпуск, версия и дата не назначены

- Продолжать переносимый Rust и Linux CI, не вводить Windows-only зависимости в общий слой.
- Перед продуктовым выпуском определить поддерживаемые дистрибутивы/архитектуры и формат установки; затем проверить egui, диалоги, доступность, права, регистр имён и symlink на выбранных системах.
- Принять установку, обновление/удаление и сохранность внешней SQLite, CTF/экспорты и фактическую производительность. CI на Linux сам по себе не означает выпущенный desktop-продукт.

Linux имеет собственную матрицу приёмки и не блокирует Windows 1.1 или отдельный macOS-выпуск.

## Backlog без обещания включения в 1.1

USB-привязка и привязанное пересканирование возвращаются только после отдельного решения и реальных проверок идентичности/конфликтов/отключения устройств. Они не нужны локальному анализатору выбранной папки. Подпись Windows, новые варианты CTF, потоковый CTF и дальнейшее снижение памяти/задержек также оцениваются отдельными задачами; выпуск 1.0 от этого не открывается заново.

## Постоянные инженерные условия

Исходные пользовательские CTF — только для чтения; правки на копиях, экспорт только в новые файлы. Неподдержанное CTF не теряется молча. Нет выполнения каталогизированных файлов, чтения содержимого/хеширования, миниатюр или сети по умолчанию. Совпадение метаданных не доказывает резервную копию. Публичные PR/CI содержат код, синтетику и очищенные агрегаты; каталоги, лицензии, реальные пути и неочищенные снимки остаются приватными.

Версия исходников и acceptance опубликованной 1.0 не меняются ради будущего плана. Для следующего кандидата readiness и матрица принимаются отдельно, по его точному SHA и платформенному scope.
