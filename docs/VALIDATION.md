# Проверка WhereIsIt AI

В реальную SQLite-базу импортированы **44 диска и 3 046 027 записей**. Обратный экспорт этой базы в CTF имеет тот же размер и SHA-256, что и предоставленный оригинал. Независимое чтение четырёх пар CSV/Parquet подтвердило совпадение всех значений, включая 321 реальный видеофайл размером больше 4 GiB. Приём новых CTF оригинальным WhereIsIt и сборка macOS остаются отдельными незавершёнными проверками.

Это отчёт о проверенном состоянии и оставшихся ограничениях, а не утверждение о завершённой проверке всех платформ. После финальных изменений ядра и схемы прошли 26 release-тестов, `cargo fmt --check` и Clippy для всех targets с `-D warnings`. Окончательная Windows GUI-сборка с колонкой Disk проверена в Wine на двух томах с одинаковыми относительными путями. Windows CLI дополнительно открыл реальную базу из 3 млн записей; статистика и точное число результатов сложного запроса совпали с Linux.

## Реальный импорт и целостность

Источник: [validation-metrics.json](validation/validation-metrics.json).

| Показатель | Измеренное значение |
|---|---:|
| Дисков | 44 |
| Записей | 3,046,027 |
| Импорт, секунд | 586.594 |
| Пиковый RSS дочернего процесса Linux | 828,520 KiB (809.1 MiB) |
| SQLite после импорта и checkpoint | 2,537,275,392 байт (2.363 GiB) |
| `PRAGMA quick_check` | `ok` |
| Финальный checkpoint импорта | `[0, 0, 0]` |

Импорт занял **9 минут 46,594 секунды**. Указанный пик памяти измерен для дочернего процесса в Linux; он не является замером нативного клиента Windows/macOS. После создания кэшей анализа размер базы в этом прогоне составил **2,631,045,120 байт**. Проверка внешних ключей после операций не обнаружила ошибок. Источник: [benchmarks.json](validation/benchmarks.json).

Выпускная отдельная компактная копия имеет размер **2 161 020 928 байт (2,013 GiB)**; готовый ZIP — **419 970 049 байт**. В ней сохранены все 44 тома и 3 046 027 записей; повторно проверены quick_check, внешние ключи, CRC архива и полное совпадение SHA-256 файла внутри ZIP с компактной копией. Рабочая исходная база осталась сохранена. См. [database-package.json](validation/database-package.json).

До упаковки удалены два неиспользуемых индекса (в сумме 430 108 672 байта страниц), а индекс дубликатов заменён покрывающим `(kind,name_norm,size)`. Навигация, поиск по пути и по диску после удаления проверены; [removed-indexes.json](validation/removed-indexes.json). Размер собственной БД существенно больше исходного CTF (144 766 574 байта). В ней хранятся рабочие записи, пути, поисковые индексы и исходные непрозрачные метаданные для обратимого экспорта. Полную компактность исходного CTF этот результат не воспроизводит; это явный компромисс текущей реализации. Импорт пока материализует каталог в памяти, потоковый импорт и его отмена не реализованы.

## Поиск: базовый измеренный прогон

[benchmarks.json](validation/benchmarks.json) получен на Linux x86-64: 9 видимых CPU, cgroup quota примерно 8 CPU, лимит памяти 8 GiB. Использовалась release-сборка и прогретый файловый кэш; одновременно могла выполняться другая работа. Каждый API-запрос открывает SQLite-соединение. «Первый» ниже означает первый запрос в последовательности, **не холодный запуск системы**.

Измерялась первая страница до 250 записей через быстрый поиск. Точный подсчёт совпадений выполнялся отдельной операцией; числа совпадений в таблице не означают, что каждый быстрый запрос считал весь результат.

|---|---:|---:|---:|---:|
| Первая страница всего каталога | 3,046,027 | 16.120 | 7.401 | 10.200 |
| Подстрока в кириллическом имени | 93 | 14.761 | 6.431 | 7.093 |
| Подстрока в латинском имени | 1,080 | 31.208 | 13.171 | 22.332 |

| Путь + расширения музыки | 3,999 | 44.466 | 46.414 | 53.429 |
| Маска имени *.mkv | 12,664 | 30.062 | 29.021 | 33.006 |

Первый небольшой тест категории вернул 7 ожидаемых записей. Дополнительно проверена действительно большая ветка: **374 259 записей**, первая страница 250 строк — 1 888,031 ms, медиана четырёх повторов — **1 129,943 ms**, максимум — 1 932,059 ms; точный подсчёт с одной строкой — 2 150,692 ms. Независимый рекурсивный SQL-подсчёт совпал. Обе временные категории и их назначения удалены; перед упаковкой категории/связи были пусты. Источник: [large-category.json](validation/large-category.json). Подтверждена работа запросов с `AND`, `OR`, `NOT`, скобками, расширениями, размерами, масками имён и кириллицей; таблица не является гарантией времени для любого произвольного выражения.

Первая операция в последовательности не равнозначна построению всех индексов и кэшей в новой пустой базе; состояния кэшей и нагрузка между прогонами не были изолированным A/B-экспериментом.

| Область | Файлов-участников | Первая операция позднего прогона, ms | Страница p50, ms | Максимум страницы, ms |

В финальной схеме добавлен покрывающий индекс `(kind,name_norm,size)`. Отдельный полный прогон с ним построил те же **537 567 групп / 1 855 534 участника** за **22 856,399 ms**; собственно группирующий SELECT выполнился за 530,538 ms. Заполнение и сортировка полного кэша остаются основной частью этой операции. Источник: [covering-index-benchmark.json](validation/covering-index-benchmark.json).

В код массового импорта добавлен `PRAGMA optimize=0x10002` до commit; статистика создаётся в той же транзакции. Удаление лишних индексов и окончательный покрывающий индекс входят в первую опубликованную схему. Полный импорт с этими последними DDL-изменениями ещё раз не измерялся: указанное время 586,594 s относится к исходному полному прогону.

Число участников совпадает с базовым прогоном во всех трёх областях. Поздний прогон подтверждает быстрые последующие страницы, но не позволяет обещать миллисекундный полный первичный анализ всего каталога: первая операция для всех файлов здесь заняла около 25,8 секунды.

## Независимая проверка CSV и Parquet

[QA_EXPORT.md](QA_EXPORT.md) и [export-independent.json](validation/export-independent.json) описывают независимый аудит стандартным Python `csv` и **DuckDB 1.4.1**. Аудитор читал готовые файлы, нормализовал Parquet NULL в пустое CSV-поле и сравнивал все значения построчно. У всех наборов совпали имена, порядок и количество 15 колонок.

| Набор | Строк | Совпадение всех значений | Строк с кириллицей в имени/пути | Размер > 4 GiB |
|---|---:|---|---:|---:|
| music_sample | 603 | Да | 419 | 0 |
| small_disk | 11 | Да | 0 | 0 |
| music_duplicates | 32,889 | Да | 21,327 | 0 |
| large_movies | 321 | Да | 320 | 321 |

Дополнительная выборка больших фильмов закрывает конкретный пробел первых трёх наборов: проверен **321 файл от 4 316 109 809 до 40 898 551 720 байт**. Parquet хранит размеры в `BIGINT`; Python получил точные целые числа, совпавшие с десятичным CSV без преобразования через float. Все 321 Unix-даты остались NULL/пустыми полями, а исходные локальные DOS-даты доступны отдельной строкой без выдуманного UTC-смещения.

## Обратимость SQLite → CTF

Экспорт из собственной БД занял **11.265 секунды** в базовом прогоне. Сервисный замер и отдельный независимый SHA-256-аудит подтвердили:

- Исходник: **144 766 574 байта**.
- Результат после импорта в SQLite и экспорта: **144 766 574 байта**.
- Оба SHA-256: `f9339112d0a2b3da114cb4f4efa026d4501da0933d294f01f02896fda08f33d5`.

Для этого неизменённого каталога подтверждено сохранение всего исходного файла. Это дополняет отдельную прямую проверку reader → writer и синтетические проверки создания/изменения каталога. Оно не доказывает, что оригинальный WhereIsIt примет любой новый файл, созданный из сканирования. Детали: [CTF_FORMAT.md](CTF_FORMAT.md).

Новые собственные категории и теги пока не имеют подтверждённого отображения в CTF. Обычный экспорт отклоняет их; явное `allow_lossy:true` допускает пропуск с флагами в результате. Неподдерживаемые варианты CTF не угадываются. Неидентифицированные данные остаются непрозрачными; не все исходные описания доступны для поиска.

## Состояние проверок сборок и интерфейса

| Проверка | Подтверждённый статус |
|---|---|
| Общий Rust gate | 26 release-тестов прошли; fmt и Clippy all-targets с `-D warnings` без ошибок |
| Набор CTF regression tests | Проверены создание/редактирование, длинные имена, Unicode/CESU-8, NUL описаний, усечения, лимиты и повреждения |
| Windows-клиент | Финальный GUI SHA d09a07c0… проверен в Wine: два тома, глобальный поиск, дубликаты и правильные Disk labels. Windows CLI открыл реальную базу и подтвердил 44 / 3 046 027 / 13 562 |
| macOS-клиент | Исходники SwiftUI подготовлены; сборка и запуск с macOS SDK не проверены в этой Linux-среде |
| Оригинальный WhereIsIt | Проверка принятия новых/изменённых CTF в отдельной VM пока pending; успех не заявлен |

Проверки Linux-сервиса и Windows-клиента под Wine не подменяют полноценные проверки на пользовательских Windows и macOS. В отчёте не приводятся частные имена файлов, пути каталога или названия дисков.
