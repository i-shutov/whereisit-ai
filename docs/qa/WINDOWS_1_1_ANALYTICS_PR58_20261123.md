# Windows 1.1 — sunburst и разрезы PR58

Разработка после [PR #87](https://github.com/i-shutov/whereisit-ai/pull/87), слитого в main `9bce933f93596a68257897cc354cb8d7e949529d`. Это следующий функциональный этап, а не выпуск Windows 1.1. Версия и acceptance выпущенной 1.0, тег и файлы релиза не меняются.

## UX и порядок переноса

Источник — [контракт PR58](../UX_REFERENCE_CONTRACT_PR58_2026-11-16.md), `ArchiveSlicesView` и `VolumeSunburstView` интерактивного прототипа. Сначала проверяются действия и снимки прототипа, затем то же поведение переносится в Rust/egui.

- Sunburst: компактный реестр дисков слева, хлебные крошки и подсветка сверху, четыре концентрических кольца из восьми семейств цветов, ранжированные ветви справа. Сегмент открывает диск/папку; хлебные крошки возвращают к родителю; явное действие поиска открывает соответствующий scope.
- Разрезы: выбор каталога/диска и категории, компактные итоговые показатели, панели распределений и переходы в карту/поиск. Неизвестные данные показываются явно; аналитика не запускает сканирование или чтение содержимого.
- Обычная смена вкладки сохраняет состояние. Явный переход в поиск начинает новый scope согласно PR58 и не меняет сохранённый аналитический scope.

## Данные и безопасность

Суммируется **записанный логический объём файлов**: каждая строка `kind=file` учитывается один раз, включая файлы внутри архивов. Строки `directory` и `archive` с агрегатными размерами не прибавляются. Это согласуется с `Volume.total_bytes`; это не физическая занятость диска, не размер сжатого архива и не доступное место на подключённом USB.

Группировки — альтернативные распределения одной выборки. Их нельзя складывать между собой. В распределении по категориям у файла с несколькими назначениями выбирается категория с минимальным ID; без назначения используется отдельный раздел. Фильтр категории проверяет точное назначение указанного ID, поэтому файл с несколькими категориями доступен через каждую из них, но в одной диаграмме его объём учитывается один раз. Пустая выборка, нулевой размер, неизвестные видеополя и отсутствующие физические параметры не заменяются демонстрационными значениями.

Совпадение имени/размера показывает кандидатов по метаданным, не равенство содержимого и не наличие резервной копии. Повторные записи на одном носителе не доказывают наличие на разных дисках. Удаления, команды очистки и готовые скрипты не создаются.

Read-only агрегация работает вне UI-потока. Отмена, замена запроса и закрытие/смена каталога инвалидируют поздние ответы. Размер отображаемого дерева ограничен; скрытые ветви и их объём должны быть обозначены, а итоговые суммы не должны молча становиться частичными.

Service-протокол: `analytics_prepare` регистрирует ограниченный токен задания до запуска worker, `analytics` читает SQLite через read-only соединение, `analytics_cancel` отменяет токен и прерывает активный SQLite-запрос. Это исключает гонку «отмена раньше старта». Запрос содержит `volume_id`, `folder_entry_id`, `category_id`, `group_by`, `highlight_query`, `max_depth` и `max_nodes`; результаты содержат контрольные итоги, альтернативные распределения, хлебные крошки, дерево и явный признак ограничения. Ошибка не публикуется как нулевая успешная выборка.

## Проверка

Контрольные SQLite и снимки — только синтетические, отдельно от репозитория. Исходный пользовательский CTF для этого этапа не открывается. Публичная запись содержит только код, синтетические тесты и очищенные результаты.

| Блок | Необходимое свидетельство |
|---|---|
| Прототип | Browser: кольца/палитра/ранжированные ветви, группировки, подсветка, папка/родитель, разрез → карта/поиск, сохранение состояния |
| API | Контрольные суммы и независимые распределения, Unicode, категории, архивные потомки без двойного счёта, нулевые файлы, отмена и пределы |
| Native | Реальное взаимодействие на 60 синтетических дисках, совпадение итогов с SQL, переходы и возврат, отмена/ошибки/неизвестные поля |
| Производительность | Синтетический большой каталог; задержка, память и явные пределы, без заявления о полном пользовательском каталоге |
| Интеграция | Тесты, Clippy, сборка и CI точного SHA; исходная SQLite сохраняет хеш |

## Фактический checkpoint — 23 ноября 2026

Изменения подготовлены в [PR #88](https://github.com/i-shutov/whereisit-ai/pull/88). Прототип проверен в браузере **до** переноса в native: группировки, подсветка, папка/родитель, разрез → поиск/карта и сохранение scope; окна 1366×768 и 1024×768. Девять тестов, lint и production build прошли.

Native проверен реальным управлением Rust/egui в Windows 11 Administrator RDP на **60 синтетических дисках**: 600 записей, 540 файлов, 60 папок структуры, 2 391 877 355 152 логических байта. Расширения: 480 MKV и 60 TXT; три категории по 180 файлов. Суммы сверены с независимым SQL. Проверены Unicode-строки, группировки, подсветка, ветви/хлебные крошки, переходы в поиск, независимое состояние Map/Slices и сохранение папки после Apply. Поиск из папки возвращает восемь MKV и ноль TXT, хотя TXT существует в корне диска; переход категории возвращает ровно 180 записей. Единая индексированная mesh устраняет швы внутри сектора, сохраняя реальные границы файлов; итоговая mesh-сборка повторно проверена в GUI.

Большой синтетический каталог: 300 600 записей / 300 540 файлов. GUI показывает полные итоги и явно сообщает об ограничении дерева. Отмена подсветки показывает «Анализ отменён» с ручным повтором, без автоматического перезапуска. Хеши синтетических SQLite до/после GUI совпали; базовый хеш снимался после закрытия генератора и его WAL checkpoint.

Производительность **analytics API**, не поиска: семь измерений на большом синтетическом каталоге, `max_nodes=128`, глубина 4, тёплый файловый кеш, новый процесс/соединение на запрос. p50 **5 572 мс**, p95 nearest-rank **5 823 мс**, максимальный sampled working set **10 948 608 байт**, private bytes **8 577 024**. Это фоновая агрегация; cold-cache, полный пользовательский каталог и завершённая подсветка большого каталога здесь не сертифицированы. Замеры выполнены без параллельной сборки/GUI-автоматизации.

Rust: **225 тестов в 22 наборах PASS**, строгий Clippy трёх затронутых пакетов с all-targets/all-features и release-сборка PASS. После последнего изменения только mesh-отрисовки повторены **69 native-тестов**, строгий native Clippy и release-сборка — PASS. Точный финальный GitHub head и CI фиксируются в PR; локальный и серверный коммиты сверяются по дереву исходников.

В проверенном объёме открытых P0/P1 не обнаружено. Неблокирующее ограничение: combobox выбранной категории может показывать «Категория #ID», хотя строки диаграммы и результаты сохраняют Unicode-имя. Сводная аналитика кандидатов в native явно недоступна; демонстрационные видеополя и физическая ёмкость не подменяют реальные данные. Это первый аналитический срез, **не весь релиз 1.1**: локальный анализатор, оставшаяся функциональность и приёмка установленного обновления 1.0 → 1.1 остаются впереди. Пользовательский CTF не открывался и не изменялся; версия, acceptance и артефакты Windows 1.0 не менялись.
