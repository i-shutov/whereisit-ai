# Windows 1.1 — локальный анализатор PR58

Следующий этап после вкладок (#87) и sunburst/разрезов (#88). Это разработка Windows 1.1, не новый выпуск и не повторное открытие acceptance Windows 1.0. Источник UX — `LocalDiskAnalyzer` интерактивного PR58 и [контракт](../UX_REFERENCE_CONTRACT_PR58_2026-11-16.md).

## Контракт

Порядок: изменения в прототипе → реальное взаимодействие в браузере → перенос того же сценария в Rust/egui → реальные синтетические GUI-проверки. Сохраняются верхний выбор папки, сводка выбранного источника, шесть режимов, дерево с sunburst и список проверки.

- Пользователь явно выбирает папку. Анализ читает имена, типы, размеры и время изменения; не открывает содержимое файлов, не вычисляет хеши и не запускает файлы. Каталог не пополняется автоматически.
- Режимы: дерево/карта, классификация кэшей и сборок, крупные/старые файлы, кандидаты по метаданным, сверка с каталогом, изменение размеров относительно явно сохранённой базы.
- Совпадение нормализованного имени и точного размера — кандидат. Совпадение одного размера или имени — отдельный слабый признак; ни один не доказывает равенство содержимого, наличие физического носителя или резервной копии.
- Сканирование идёт вне UI-потока. Временные результаты изолированы от постоянного каталога, выдаются постранично. Прогресс, отмена, ошибки доступа, пропущенные ссылки и неполнота показываются явно. Поздний ответ не заменяет новый источник или результаты другого каталога.
- Символические ссылки и Windows reparse points не обходятся. Корень и его предки проверяются; ссылка на внешний каталог и цикл не расширяют область анализа. Некодируемые имена не подменяются строками с потерями.
- Список проверки — отбор метаданных для нового CSV. Нет удаления, команд очистки и перезаписи существующих файлов. Экспорт не создаётся внутри анализируемой папки и не заменяет каталог/его sidecar.
- База роста фиксирует момент измерения и выбранный источник. Отрицательная разница означает наблюдаемое изменение размеров, а не подтверждённое удаление; ошибки и неполные обходы не превращаются в успешное сравнение.

Native GUI наблюдался в viewport 1320×760; проверки геометрии на 1366×768 и 1024×768 — отдельные headless egui-регрессии, а не заявление о полном физическом прогоне каждого размера. Это не завершённая приёмка Windows 1.1: обновление установленной 1.0 → 1.1, rollback, полный каталог и установщик проверяются на отдельном кандидате после интеграции. Hosted Linux/macOS compile/tests не заменяют физическую GUI-приёмку этих платформ. Небольшие смешанные RU/EN подписи и отображение корневой строки роста требуют полировки; каталог показывает кандидатов, а не доказанные копии. Прототипный выбор реальной папки и отмена в браузере не проверены.
