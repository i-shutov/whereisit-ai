# Fast catalog open and explicit integrity validation

Opening an existing egui catalog previously ran SQLite quick_check, foreign-key checking and full record counts before the first page. One full-catalog service observation on Windows 11 measured 39.46 seconds for validation before a 10.62 ms first page. That is readiness cost, distinct from warm query latency.

Normal Open now invokes `probe_catalog`: a read-only transaction checks schema version 1–3, required object kinds and preparation of fixed zero-row column/FTS statements. It does not count records or check data integrity. Missing files, unsupported versions and missing/incompatible schema objects are refused without creating or migrating a database. A matching schema shape is not proof of FTS correctness or all data integrity.

The inspector explicitly says integrity is not checked. Catalog → Check integrity runs the existing full validator asynchronously, on explicit request. Success says the last SQLite integrity check passed; this describes its snapshot, not a permanent guarantee. A failed or malformed check closes the current catalog and clears selection/results and catalog-scoped controls. Request ID and catalog path prevent a prior catalog's result from verifying the current catalog. Creation continues to use init. Existing normal catalog operations retain their prior connection behavior; only probe and full validation are read-only contracts.

Synthetic service tests cover supported versions without changing the source bytes, stale counters allowed by probe but refused by full validation, and missing/malformed/future/missing-column/wrong-object inputs. GUI model/worker tests run the actual Open-to-first-search chain with a full-validation trap, reject malformed probe replies, exercise explicit validation failure cleanup and reject prior-catalog replies. The status shares the existing inspector header row and does not consume a new row of controls.

Local focused validation: 8 maintenance tests, 45 egui tests with isolated QA features, scoped formatting and strict Clippy passed. An exploratory local debug CLI series on the full imported derivative (30 warm iterations, 250 rows, uncontrolled OS cache) measured probe p95 2.96 ms and probe-through-first-page p95 23.04 ms. These are service timings, not GUI or release-installer acceptance. Exact-head hosted CI and installer observations are recorded in the PR validation section.

The PR also contains the separately prepared empty-CTF/absent-range refusal fix, documented in [CTF empty-range regressions](CTF_EMPTY_RANGE_REGRESSION_20261121.md). Both new parser regressions failed on main and passed after the checks. No private files, paths, queries, source fingerprints, raw reports, screenshots or licenses are included.
