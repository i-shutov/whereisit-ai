# UX16 — video-extension search, native Win32 + SwiftUI (2026-11-02)

**What it does:** Win32 Video files / All formats (Ctrl+Shift+V), SwiftUI Video files / All formats (Command+Shift+V) toggle an editable `type:video` predicate in the global catalog search. If a query exists, `name:Герой OR name:Hero` becomes `(name:Герой OR name:Hero) AND type:video`; toggling off restores the initial expression. Empty query becomes `type:video`. Exceeding 4096 UTF-8 bytes refuses the transformation. "This disk" remains a separate explicit scoped search.

**Truth boundary:** this is only an indexed metadata filename-extension heuristic for mkv, mp4, avi, mov, m4v, webm, mpg, mpeg, wmv, ts, m2ts, vob, flv. Unknown `type:` values are rejected. There is NO film-title recognition, codec decoding, live file presence, verified byte/hash comparison, USB presence inference or auto-delete. Linked CTF stays source-SHA-generation-pinned read-only; personal physical pairings remain independent.

**Synthetic CI:** run `cargo test --workspace` for a two-disk, five-record synthetic fixture, grouped OR query, Unicode and uppercase extension/value, disk scope, unsupported type and no TXT/PDF results; run `python tools/qa/test_usb_disk_locator_contract.py`, Linux/Windows x64/macOS ARM64+Intel native builds, offline acceptance, integration and installed RC2→RC3 upgrade checks, all at the exact PR HEAD.

**Manual hardware and UX checks not covered by CI:** Win10/11 and Mac Intel/ARM Ctrl+F/Command+F, complex query, toggle on/off, focus and screen-reader labels, 880/1180/1366px HiDPI, linked source changed between searches, page invalidation, no real drive-letter guessing, copy mode transition. ISO movies may be missed; invalid .mkv files may be included. Do not publish any owner CTF/SQLite, private paths/names/generation SHA or raw benchmark logs. Earlier 44-disk/3,046,027-row real-data acceptance is genuine but does not establish UX16 p95. Stable 1.0 remains blocked, RC3 unsigned prerelease and PR #57 draft/unmerged.
