# Windows 1.1 — вкладки и рабочие пространства PR58

Первый функциональный этап после выпущенной Windows 1.0, ветка `feature/windows-1.1-workspaces-pr58`. Это разработка 1.1, не новый stable-выпуск. Тег/файлы 1.0, VERSION и опубликованный acceptance не переписываются.

## Контракт

Источник UX — [PR58](https://github.com/i-shutov/whereisit-ai/pull/58), `apps/ui-prototype`, [общий контракт](../UX_REFERENCE_CONTRACT_PR58_2026-11-16.md). Сохраняются пять фиксированных рабочих пространств и их порядок: **Поиск → Разрезы → Карта объёма → Носители → Локальный ПК**. Это разные представления общего каталога, а не отдельные каталоги в браузерных вкладках. Компоновка поиска, таблица и инспектор не переизобретаются.

- Обычное переключение сохраняет поисковый текст, scope, папку/историю, страницу, выделение и прокрутку. Реестр носителей имеет собственный фильтр/сортировку и состояние.
- Явный переход «Поиск» из реестра начинает новый поиск по выбранному диску, очищая прежние запрос/папку/категорию/историю согласно PR58; это действие отличается от обычного переключения вкладки, которое сохраняет контекст.
- Изменение/закрытие каталога инвалидирует данные старого каталога. Поздний ответ не заполняет новый каталог или другое рабочее пространство.
- Модальные окна подавляют фоновые действия; скрытое пространство не получает пользовательские сочетания клавиш. Клавиатурная навигация вкладок сохраняет доступность.
- Прототип хранит посещённые компоненты в памяти, а непосещённые не загружает заранее. Перезагрузка страницы начинает новый demo-сеанс; сохранение пользовательского каталога на диск этим не имитируется.

## Сначала прототип

Исходная условная отрисовка размонтировала пространство при переходе и теряла его контекст. Новая оболочка сохраняет посещённые пространства, добавляя роли tablist/tab/tabpanel и навигацию стрелками/Home/End без смены компоновки PR58. Обработчики поиска работают только в активном пространстве. Асинхронные аналитические ответы привязаны к scope и поколению запроса; неудачный запрос можно повторить, поздний ответ не заменяет новое состояние.

Всё содержимое сервера прототипа — синтетическая модель. Доступность демонстрационной sunburst/аналитики в браузере не означает, что они реализованы в Rust.

## Затем Rust/egui

Первый native-перенос включает оболочку вкладок и реальные рабочие пространства **Поиск** и **Носители** на существующих Rust/SQLite операциях. Поиск сохраняет свой контекст при скрытии. Реестр показывает записанные метаданные и локальные свойства, позволяет открыть свойства или явно перейти к поиску диска.

Разрезы, карта объёма и локальный анализатор обозначены как ещё недоступные: их реальные service/API и native-представления — следующие этапы 1.1 из [roadmap](../ROADMAP.md). Демонстрационные числа/диаграммы не переносятся в продукт. USB-привязка остаётся отключённой. Смена вкладки сама по себе не открывает базу повторно и не сканирует файловую систему.

## Проверка

| Блок | Сценарий |
|---|---|
| Сборка прототипа | Замороженный bun.lock, TypeScript lint и Vite production build; без React/Node в native-пакете |
| Async regression | Ошибка → повтор, смена scope → поздний ответ, деактивация → возврат, успешный A → ожидающий B → возврат A |
| Прототип в браузере | 60 demo-дисков, запрос и выбранный файл → Носители с отдельным фильтром → возврат; папка/Назад, пагинация/прокрутка; стрелки/Home/End, F2 в другом пространстве; 1366×768 и 1024×768 |
| Rust regression | Сохранность состояния поиска/истории/прокрутки, отдельное состояние реестра, явный переход scope, поздние ответы и смена каталога, активные shortcuts/модальные окна, отсутствие команд от недоступных вкладок |
| Native GUI | Отдельный development EXE и новая синтетическая SQLite на 60 дисков; переключение, страница 251–500, выделение/папка/Назад, реестр и переход к поиску, недоступность будущей аналитики |

Полные результаты и снимки сохраняются локально вне Git. В публичные изменения попадают только код, синтетические регрессии и очищенные агрегаты. Настоящий пользовательский CTF для этого этапа не используется.

## Фактический checkpoint

- Прототип: frozen install, TypeScript lint, production build, четыре async-регрессии и две регрессии явных переходов — PASS. В реальном браузере на 60 demo-дисках проверены сохранение запроса/выделения/дискового фильтра/scope, папки/Назад, страницы 251–500 и внутренней прокрутки при возврате; стрелки/Home/End и отсутствие F2-перехвата скрытым поиском. Проверены viewport 1366×768 и 1024×768. Отдельно проверено, что явное действие реестра очищает старую папку/запрос/Назад и открывает новый дисковый scope, а последующие обычные переключения снова сохраняют новый запрос.
- Native: 61 тест и Clippy с `--all-targets --all-features -- -D warnings` — PASS. Это не подмена настоящего GUI-прогона.
- Обнаружена и исправлена привязка development WebSocket Vite к внешним интерфейсам. После исправления и HTTP, и WebSocket фактически слушают только loopback; открывать брандмауэр не требуется. Это отдельный дефект тестового прототипа, не native-продукта.
- Native GUI: предварительный EXE запущен на новой синтетической SQLite; окончательный интерактивный прогон ещё не принят. Системный запрос брандмауэра от предыдущего запуска Node требует ручного закрытия; разрешение на сеть не выдавалось. Нельзя отмечать GUI PASS по факту запуска процесса.

Перечень сценариев выше не означает автоматического PASS. Windows 1.1 целиком не объявляется выпущенной; реальные аналитические пространства остаются следующими этапами.
