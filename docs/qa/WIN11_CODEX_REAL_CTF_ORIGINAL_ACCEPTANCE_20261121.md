# WhereIsIt AI 1.0 — задание Codex для Win11: настоящий CTF и оригинальная WhereIsIt

**Владелец:** пользователь. **Исполнитель:** Codex CLI в интерактивном RDP/терминале Windows 11 Pro x64 **под Administrator**. **Приоритет:** Win64 Rust/egui. **Статус на дату задания:** NOT_RUN на личном CTF и в оригинальной программе; stable 1.0 = NO-GO.

## 0. Цель и критерий завершения

Провести воспроизводимую независимую приёмку на реальной Win11, не подменяя работу с оригинальной WhereIsIt проверками нашего парсера самим собой. Отдельно проверить:

1. Настоящий нативный Rust/egui Win64 GUI: 60 сгенерированных томов, Unicode, Boolean-поиск, инспектор/Back, категории, CSV/JSON/Parquet без перезаписи, scan/cancel/rollback, плотность интерфейса.
2. Реальный частный CTF: неизменность исходника по SHA-256, чтение 3M+ записей (фактические числа определять из файла, не предполагать), полный CTF→SQLite→CTF, экспорт и доступные 15-полевые проверки.
3. **Модифицированный экспортированный CTF открыть в оригинальной WhereIsIt.** Это независимый критический тест совместимости, отсутствующий в прежнем evidence.
4. Реальная поисковая производительность на Win11: воспроизводимые серии, p50/p95, отдельно время синхронизации/импорта, RSS/память и disk I/O. Целевой p95 поиска ≤150 мс.
5. Инвентаризация оставшихся блокеров: прямое CTF GUI, описания и неизвестные поля, PR58 parity, USB hardware, подпись.

Каждый тест маркируй PASS, FAIL, PARTIAL, BLOCKED или NOT_RUN и привязывай к исходному Git SHA, бинарнику и локальному идентификатору evidence. Отсутствие инструмента или возможности управлять оригинальным GUI — BLOCKED, а не фиктивный PASS. Самостоятельно тег `v1.0.0` не создавать, `stable_ready` не менять.

## 1. Входные данные и полномочия

Пользователь предоставит **на самой Win11**, без загрузки в GitHub/чат:
- один или несколько исходных `*.CTF` — предпочтительно большой исходный Catalog 3.00, исторически 44 тома / 3 046 027 записей; версия и состав проверяются фактически;
- оригинальную легальную Windows-программу **WhereIsIt** той версии, которой создан/читается CTF, и при необходимости её личную лицензию. Пользователь может установить программу сам; Codex не ищет сомнительные установщики, не обходится без лицензии и не копирует ключи;
- исходники `i-shutov/whereisit-ai` и скачанные с **успешного GitHub-hosted Actions run** артефакты Win64; необходим доступ к интерактивной RDP-сессии Administrator.

Разрешены локальные проверки, тестовые копии CTF, отдельные временные SQLite и новые файлы вывода; запуск Codex под Administrator прямо разрешён `AGENTS.md`. Запрещены работа с другими проектами/runner services, отключение Defender/SmartScreen, изменение system-wide Execution Policy, удаление или изменение авторитетного исходного CTF, запись в него из original WhereIsIt, бесконтрольный поиск всех личных файлов, публикация содержимого или приватных SHA CTF.

**Разделение контуров:** `win11-whereisit` GitHub Actions service в Session 0 не подтверждает настоящую RDP GUI-приёмку. W1 runner smoke уже PASS в [run #44888299971](https://github.com/i-shutov/whereisit-ai/actions/runs/44888299971), это не W2.

## 2. Каталог тестирования на Win11

Предложи/создай **отдельный приватный** workspace, например `C:\WhereIsItQA\private-acceptance\`, вне любых Git worktree; предварительно убедись в достаточном свободном месте для исходника + рабочих CTF + SQLite/WAL + CSV/Parquet (несколько гигабайт, фактический объём исходника учти). Не удаляй существующие папки; если уже занято — новый уникальный каталог.

Схема (имена условные, не экспортировать реальные пути):
- `source\original-master.CTF` — *локальная проверенная копия* из пользовательского источника, только для чтения;
- `working\vendor-edit.CTF` — отдельная копия для изменений **оригинальной** программой;
- `working\rust-input.CTF`, `working\rust-output-modified.CTF` — раздельные входы/выходы нашего инструмента, никогда не перезаписывать `original-master.CTF`;
- `derived\...` — SQLite, WAL, Parquet/CSV, тестовые CTF и промежуточные дампы, приватно;
- `evidence\...` — локальные полные отчёты и снимки;
- `redacted\...` — только проверенные, вручную очищенные агрегаты для публичного GitHub.

Для пользовательского исходника и каждой рабочей копии перед экспериментами локально рассчитать SHA-256 и размер. Для master повторить SHA-256 после **каждого** комплекса проверок и в конце. Исходник не должен быть аргументом `export_ctf`, `import_ctf` output, редактора или записывающего API. При несовпадении SHA — **остановка P0**, сохраняй локальную диагностику. Никакой очистки/перезаписи без явного согласования.

## 3. Точный кандидат и environment preflight

1. Проверить Windows 11 Pro x64, build, процесс Administrator, настоящий интерактивный desktop, версию PowerShell, доступность `git`, `cargo`, `rustc`, `py`/`python`, `codex` и оригинальной WhereIsIt. В `RUNNER_SMOKE_PASS` перечислялась только доступность инструментов из PATH *службы*; не считать это доказательством их отсутствия у Administrator в RDP.
2. Для P0 категорий использовать **точно проверенный** на дату задания PR #73 SHA `40c6b695958e49cbdad78affa314b139dd28d61b`, CI [#44891158178](https://github.com/i-shutov/whereisit-ai/actions/runs/44891158178), если PR HEAD не сменился. При смене HEAD сначала проверить новую exact-head CI. В этом run содержатся `WhereIsItAI-egui-qa-windows-x64` и `WhereIsItAI-egui-Win64-installed-QA-unsigned`. Это **unsigned** QA, не stable.
3. Сверить origin, run ID, source SHA, manifest и SHA-256 скачанного пакета с оригинальным hosted Actions run; не брать двоичные файлы из внешних зеркал. Использовать `docs/qa/WIN11_EGUI_RDP_ADMIN_QA_HAPPYPATH_20261121.md` и `tools/qa/windows11-egui/Invoke-VerifiedWin11EguiRdpQA.ps1` из доверенного `main`. Launcher может требовать внутренний QA runner с UTF-8 BOM.
4. Записать текущую фактическую `atlas --sqlite-version`. **Важно:** `tools/qa/offline_ctf_v3.py` исторически строго ожидает SQLite `3.51.3`; с более новым `libsqlite3-sys`/`rusqlite` CLI проверка может дать ложный BLOCKED по версионному guard. Если версия расходится с проверенным CLI, **не менять ожидаемое число ради зелёной галочки**. Сначала диагностировать pinned build/ABI, завести отдельный исправляющий тест/PR при необходимости. Не заявлять real CTF PASS, если проверка не исполнилась.
5. В Git не смешивать PR73 и main слепым `git pull`. Выделить отдельный чистый checkout/worktree для каждого исходного SHA. Всегда записывать использованный actual HEAD.

## 4. W2: живой Rust/egui GUI на синтетике

В интерактивной Administrator RDP-сессии выполнить проверенный launcher:

`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\qa\windows11-egui\Invoke-VerifiedWin11EguiRdpQA.ps1 -ArtifactDirectory '<ПУТЬ_К_РАСПАКОВАННОМУ_ACTIONS_АРТЕФАКТУ>' -ExpectedCommit '40c6b695958e49cbdad78affa314b139dd28d61b' -DiskCount 60`

Проверить 60 виртуальных дисков, более 250 результатов/пагинацию, быстрый глобальный и scoped поиск, Ctrl+F/Back/выделение/скролл, RU/EN, light/dark, модальные формы, свойства/наклейки, категории с одинаковым названием по разным ID, назначение/снятие/повторное назначение, CSV/JSON/Parquet и no-clobber, scan/cancel/rollback и SQLite quick_check. Часть действий в `-ManualReview` требует ручного клика/скриншота — Codex не должен выдавать CLI PASS за GUI PASS.

Зафиксировать экран в 1024×768 и 1366×768 без изменения настроек других сеансов; сравнить с PR58. Установленный отдельный Inno egui Win64 QA проверять **отдельно** по `docs/qa/WIN11_WIN64_EGUI_MANUAL_CHECKLIST_20261121.md` (install/launch/restart/uninstall, сохранность внешнего SQLite). Не считать preview запуск подтверждением установленного lifecycle.

**Ограничение текущего Rust/egui:** `apps/desktop-egui/src/main.rs` принимает `--catalog <existing.sqlite>`, а GUI сейчас не предоставляет прямого открытия внешнего `*.CTF`. Real CTF тестировать через native `atlas-service`/`ctf-format`/`atlas-cli` и производный SQLite, затем отдельно открывать SQLite в egui. Прямое CTF GUI из PR58 / старых native клиентов отмечать отдельным незакрытым feature-parity gate, а не подменять CLI работоспособностью.

## 5. W5-A: настоящий CTF, исходник строго read-only

1. Проверить сигнатуру/версию без произвольной интерпретации неизвестных полей. Зафиксировать агрегаты — диски, файлы/папки, число записей, время считывания, объём.
2. Если текущий exact-source CLI совместим с `tools/qa/offline_ctf_v3.py`, выполнить приватный `offline_ctf_v3.py` с `--cli`, `--expected-sha256`, новым `--output` и `--timeout-seconds 1800`. При наличии подходящего DuckDB и достаточного места — `--full-export --verify-export-parity`, иначе отметить отдельный NOT_RUN, не PASS.
3. Проверить полный CTF→отдельный SQLite→новый CTF, байтовое равенство **неизменённого** roundtrip, независимое соответствие экспортируемых 15 полей, Unicode, DOS timestamps, размеры >4 GiB, search pagination и source unchanged.
4. Отдельно выбрать несколько записей и папок для визуальной сверки с оригинальной WhereIsIt (локальный список выборки: русский/английский, длинные имена, вложенные архивы, даты и описания). Не публиковать эти строки и скриншоты без ручного редактирования.
5. `docs/CTF_FORMAT.md` — clean-room документ, **не официальная спецификация**. Непрозрачный high flag `0x10` нельзя автоматически считать потерянными описаниями; неизвестные поля сохранять как opaque. Записывать конкретные неподдерживаемые варианты, а не выдумывать семантику.

## 6. W5-B: проверка **настоящей оригинальной WhereIsIt**

Только после подтверждённой копии, достаточного места и согласованного действия в оригинальной программе:

1. Оригинальная WhereIsIt открывает `working\vendor-edit.CTF` (вторая копия, НЕ master). Проверить запускаемость на Windows 11 x64, фактическую версию приложения, число дисков/записей и выбранную локальную выборку. Если оригинальное приложение не установлено/не запускается — `BLOCKED_ORIGINAL_APP`, не считать наш CTF неверным.
2. На **маленьком полностью синтетическом** CTF проверить, открывает ли исходная программа выход нашего Rust CTF-экспортёра. Сделать контрольную безопасную правку (описание, имя или добавление тестового объекта — строго в пределах поддержанных операций), сохранить **в новое имя** и открыть в оригинальной программе. Если нет поддержки — зафиксировать текст ошибки и остановить более рискованный этап.
3. На **копии реального** CTF через native import в отдельный SQLite и проверенный `update_entry` сделать минимальное допустимое изменение **описания** одной выбранной записи и экспортировать в **новый** `rust-output-modified.CTF`. Проверить открытие/поиск/описание в оригинальной WhereIsIt и сохранность контрольных неизменённых записей. Перед запуском проверить реальные контракты `import_ctf`, `update_entry`, `export_ctf` в `atlas-service`/`atlas-core`; если операция небезопасна для обнаруженных opaque references — отказаться, отметить BLOCKED и завести баг. Категории native SQLite НЕ объявлять переносимыми в CTF без установленной семантики.
4. В обратном направлении изменить **только** `working\vendor-edit.CTF` в оригинальной программе, сохранить его отдельным файлом и проверить, что наш parser импортирует эти изменения. Проверить `source_changed` для pinned linked-CTF поколения, если тест доступен, затем явный повторный sync.
5. Сравнивать не только SHA unchanged, но и результаты **изменённого** файла в двух независимых приложениях. Один успешный unchanged byte-for-byte roundtrip не закрывает этот gate. Уточнить версию оригинальной программы и различать старую/новую модификацию CTF.

Нельзя пытаться «исправить» неизвестные CTF-байты вручную, публиковать байтовые дампы, CTF целиком, лицензионные файлы или настоящие имена/серийники дисков.

## 7. W5-C: целевой поиск на 3M+ записей

На реальном архиве при одинаковой generation и заранее закреплённых семантических запросах сделать не менее **30 warm measurements** каждого из 3–5 классов: global Boolean/Unicode, scoped-volume, по размеру/расширению, контекст выбранной папки; отдельно измерить первый cold-ish запуск и импорт/синхронизацию. Состав запросов приватный. Собирать elapsed wall-time, p50/p95, максимум, peak RSS/working set, объём WAL/диска и любые тайм-ауты; фиксировать CPU/диск/память/OS и CLI binary SHA. Не заявлять достоверный cold-cache тест без управляемой методики сброса кеша. Никакого автоматического удаления ОС-кеша.

Если p95 >150 мс — явный FAIL текущего SLO и конкретный performance profile, а не округление в PASS. Не выполнять повторные полные 3M импорты без достаточного места/контроля времени; при недоступном hardware/performance profiler — PARTIAL/NOT_RUN.

## 8. Результаты и полномочия на исправления

**Локально приватно** в `evidence`: фактическая версия original WhereIsIt, Windows build, source/CLI/GUI SHA, исходный SHA-256 CTF, замеры, full artifacts, ошибки и raw screenshots. **Не публиковать** ни CTF, ни эти полные отчёты, ни SHA приватного CTF, ни file paths, имена дисков, личные описания, tokens/licences.

**Публичный очищенный отчёт** (после просмотра человеком) содержит:
- exact Git source SHA и тип Win64 артефакта, OS build, тип проверки;
- статусы `GUI_LAUNCHED`, `CATEGORY_GUI`, `REAL_CTF_READONLY`, `CTF_UNCHANGED_ROUNDTRIP`, `MODIFIED_CTF_OPENED_IN_ORIGINAL_APP`, `PERFORMANCE_P95_150MS`, `WIN64_INSTALLER_LIFECYCLE`, `PHYSICAL_USB`;
- только агрегаты (например число томов/строк, p50/p95, длительности), а не raw names/paths/queries/hashes;
- issue P0/P1/P2 с условиями воспроизведения на synthetic fixtures и ссылками на исходники;
- явный вердикт `GO/NO-GO` для **каждого** gate и отдельно для stable 1.0.

Если выявлен дефект программного кода, разрешено подготовить **отдельную ветку**, синтетический regression test и исправление, выполнить тесты и открыть draft PR без приватных данных. **Не** сливать в `main`, не переносить/публиковать исходный CTF, не делать force-push, не менять `release/ACCEPTANCE.json` на true и не тэгировать релиз без отдельной финальной интеграционной приёмки.
